¿QUÉ HACE LA APLICACIÓN?
Es una aplicación que busca la ferretería que tenga el producto más barato 
en bolivianos (BOB) de Bolivia y que esté más cerca de la ubicación del usuario, 
aplicando los algoritmos y modelos matemáticos de Investigación Operativa II.

La idea principal es aplicar todos los métodos enseñados en la materia IOP812.

¿QUÉ FUNCIONALIDADES TIENE LA V1?
* Registro personal de usuarios mediante Google OAuth.
* Vista exclusiva para administradores/ferreteros para carga masiva y actualización 
  de catálogo, precios y stock en tiempo real.
* Buscador geoespacial y ordenamiento multicriterio AHP (Precio, Distancia, Reputación, Stock).
* Módulo de gestión de inventarios:
  - Lote Económico de Pedido (EOQ) y Punto de Reorden (ROP).
  - EOQ con Faltantes / Déficit permitido.
  - EOQ con Descuentos por Cantidad (Rangos de precios).
  - Lote Económico de Producción (EPQ) para productos fabricados en sitio.
  - EOQ Multiproducto con restricción de almacenamiento (m²).
* Módulo de Evaluación de Decisiones:
  - Decisiones bajo incertidumbre (Laplace, Wald MaxiMin/MaxiMax, Hurwicz, Savage).
  - Decisiones bajo riesgo mediante Árboles de Decisión (VME y VEIP).
* Módulo de Predicción mediante Cadenas de Markov con Estados Absorbentes para simular 
  el comportamiento de navegación y probabilidad de conversión de compradores.
* Estimación de tiempos de espera en mostrador mediante Teoría de Colas (Modelo M/M/1).

¿MÉTODOS DE INVESTIGACIÓN OPERATIVA II APLICADOS?
1. AHP (Analytic Hierarchy Process): Matriz de comparación por pares, cálculo de vector de pesos W y ratio de consistencia CR.
2. Modelos de Inventarios Determinísticos:
   - EOQ Básico: Q* = sqrt((2*D*K)/H)
   - EPQ (Producción): Q* = sqrt((2*D*K)/(H*(1 - d/p)))
   - EOQ Faltantes: S* de déficit máximo y Q* ajustado por costo p.
   - EOQ Descuentos: Optimización por tramos de precios.
   - ROP (Punto de Reorden): ROP = (d * L) + SS.
3. Decisiones Bajo Incertidumbre: Criterios Laplace, Wald (Optimista/Pesimista), Hurwicz (con coeficiente alpha) y Savage (Matriz de arrepentimiento).
4. Decisiones Bajo Riesgo: Valor Medio Esperado VME = sum(P_j * V_j) y Árboles de Decisión.
5. Cadenas de Markov Absorbentes: Matriz fundamental N = (I - Q)^-1 y Matriz de Absorción B = N * R.
6. Teoría de Colas (M/M/1): Tasa de llegada lambda, tasa de servicio mu, uso del sistema rho = lambda/mu y tiempo en cola Wq = lambda / (mu * (mu - lambda)).

REGLAS DE NEGOCIO DEL SISTEMA:
1. Ordenamiento AHP: Valida que la matriz de comparación entre Precio, Distancia, Reputación y Stock cumpla CR = CI / RI < 0.10 para asegurar consistencia en la decisión.
2. Gestión de Inventarios:
   - Aplica EOQ para productos comprados y EPQ para productos de fabricación propia en ferreterías.
   - En productos con volumen con descuento, calcula el costo total (CT) en cada tramo para determinar el lote óptimo real.
   - Notifica punto de reorden en tiempo real según ROP = (d * L) + SS.
3. Decisiones Financieras / Suministro:
   - Si no hay probabilidades conocidas, presenta la sugerencia según Laplace, Wald, Hurwicz (alpha=0.7) y Savage.
   - Con probabilidades estimadas, sugiere la alternativa que maximice el VME.
4. Cadenas de Markov:
   - Monitorea transiciones del usuario y calcula la matriz de absorción B para estimar la tasa probable de conversión a venta.
5. Tiempos de Espera (Colas M/M/1):
   - Muestra el tiempo estimado de espera en mostrador Wq para recomendar el mejor momento de visita presencial.

¿ARQUITECTURA?
La arquitectura del proyecto será una arquitectura vertical por dominio / Módulos de I.O. (Feature-First / Vertical Slices) 
app/
├── modules/
│   ├── autenticacion/  # OAuth Google, JWT, usuarios
│   ├── buscador_ahp/   # Buscador Leaflet, PostGIS, algoritmo AHP
│   ├── inventarios_eoq/# EOQ, EPQ, Faltantes, Descuentos, ROP
│   ├── decisiones/     # Incertidumbre (Wald, Savage...) y Riesgo (VME/VEIP)
│   ├── markov/     # Matrices de conversión y estados absorbentes
│   └── colas_mm1/  # Tiempos de espera y tasas lambda/mu
├── shared/         # Conexión BD, utilidades comunes de NumPy
└── main.py


Donde cada método (o tema del temario) tiene su propia carpeta dedicada, y dentro de ella habitan los archivos necesarios para hacer funcionar ese método de forma independiente.
app/modules/markov/
├── __init__.py        # Indica que es un paquete de Python
├── routes.py          # Define las rutas/endpoints (ej. POST /api/markov/simular)
├── engine.py  # Código matemático puro 
|              👉# (NumPy, cálculo de N = (I-Q)^-1 y B = N*R)
└── schemas.py  # Validación de los datos JSON de entrada y salida


En lugar de tener un solo archivo gigante como app.py o carpetas gigantescas globales, cada carpeta de módulo funciona como una mini-aplicación autónoma.
